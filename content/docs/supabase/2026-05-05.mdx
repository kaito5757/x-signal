### 1. AI生成アプリのセキュリティ懸念（Supabaseの公開テーブル問題）

| 投稿者 | Sully (@SullyOmarr) |
| 投稿日時 | 2026年5月4日 10:32（日本時間） |
| エンゲージメント | ❤️ 607 / 🔁 20 / 💬 152 |
| リンク | [元ポスト](https://x.com/SullyOmarr/status/2051112684985495776) |

**投稿内容:**

> AIで簡単に作られた（vibe coded）製品を使うのが怖い。99%の確率で、自分の情報が誰でもアクセスできる公開されたSupabaseのテーブルに置かれている。少し頭の働くハッカーならすぐに入手できるだろう。

**解説:**

この投稿は、最近流行しているAI支援の「vibe coding」（感覚的にコードを生成させる開発手法）で作られたアプリの多くが、データベースのセキュリティ設定を適切に行っていない点を強く指摘しています。特にSupabase（オープンソースのFirebase代替）では、Row Level Security（RLS：行レベルセキュリティ）をデフォルトで無効にしている場合が多く、認証なしで全データが閲覧可能になるリスクを強調。スレッドでは「Supabase自体は悪くないが、すべてのテーブルにRLSを設定し、セキュアな鍵を使って認証せよ」というフォローも投稿者自身が行っています。AIツールがコードは生成しても、データベースポリシーのような設定ミスまでは警告しないという業界の課題を浮き彫りにした、実践的なセキュリティ分析として価値の高い内容です。

### 2. SupabaseのRLS未設定によるデータ漏洩の実例報告

| 項目 | 詳細 |

| 投稿者 | antonio realoficial.com.br | viral.day (@acgfbr) |
| 投稿日時 | 2026年5月4日 11:30（日本時間） |

| リンク | [元ポスト](https://x.com/acgfbr/status/2051127270987665796) |

**投稿内容:**

> 正直、これは変わらないだろう。去年9月、ある有名なブラジル製アプリがSupabaseのURLを公開したままRLSを設定しておらず、誰でも全データをダンプ（抽出）できる状態だった。私は関係者にメールで報告し、感謝され修正すると言われた。しかし今日確認したら全く同じ状態で、最近資金調達に成功したという。無償の脆弱性報告はもうやめる。

**解説:**

Supabaseを使った実在のアプリケーションで、RLS（行レベルセキュリティ）が設定されていないためデータベースが丸ごと公開されていた具体例を挙げ、業界の杜撰さを批判した投稿です。投稿者は昨年報告したにもかかわらず修正されず、そのアプリが資金調達に成功したことに失望を表明。VC（ベンチャーキャピタル）が製品の技術的健全性ではなく人脈を重視する風潮と絡めて語っており、スタートアップのセキュリティ意識の低さと「見せかけの成長」の問題を浮き彫りにしています。優先すべき「業界動向・分析」に合致する実例ベースの警鐘です。
