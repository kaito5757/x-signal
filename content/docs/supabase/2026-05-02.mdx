| リンク | [元ポスト](https://x.com/supabase/status/2050222634542018618) |

**投稿内容:**

> SupabaseのEdge Functionsに、新しく公開可能キー（publishable key）と秘密キー（secret key）が追加され、環境変数にJWKS（JSON Web Key Set）が事前読み込みされるようになりました。

**解説:**

Supabase公式アカウントによる新機能アップデート情報です。Edge Functions（サーバーレス関数）は、FirebaseのCloud Functionsに相当する機能で、今回追加されたキーとJWKSの事前読み込みにより、認証処理のセキュリティが強化され、コールドスタート時の遅延も改善されます。JWKSはJSON Web Tokenの署名検証に使われる鍵セットで、毎回外部から取得する必要がなくなりパフォーマンスが向上します。開発者にとって実践的な改善点が多く、優先すべき新機能情報として高く評価されます。

### 2. Supabaseを避けた代替技術スタックの提案

| 項目 | 詳細 |
|------|------|
| 投稿者 | Fazt (@FaztTech) |
| 投稿日時 | 2026年5月1日 23:52（日本時間） |
| エンゲージメント | ❤️ 302 / 🔁 15 / 💬 15 |
| リンク | [元ポスト](https://x.com/FaztTech/status/2050226931392471141) |

**投稿内容:**

> 従来の技術スタック（Next.js、Supabase、Node.jsなど）を避けたい開発者が増えています。代わりに注目されている代替スタックは以下の通りです。
> 
> - フロントエンド：TanStack Start（Next.jsの代わり）
> - バックエンド：Convex（Supabaseの代わり）
> - 認証：Better-Auth（NextAuthの代わり）
> - ランタイム/パッケージマネージャー：Bun（Node.js + npmの代わり）
> - リンタ：Oxlint（ESLintより約50倍高速）
> - モノレポ：Turborepo
> 
> TypeScriptで完全にend-to-end、ルーティングからデータベースまで型安全で、開発体験（DX）が大幅に高速化されます。欠点はコミュニティがまだ小さく、スペイン語のチュートリアルが少ない点ですが、今後拡大すると予想されます。このスタックを試しますか？それとも従来のものを続けますか？

**解説:**

SupabaseをFirebase代替として使わず、Convexをバックエンドに選ぶ代替スタックを提案した投稿です。業界動向として「従来スタックからの脱却」をテーマに、各ツールの利点（高速性、型安全性）を具体的に解説しており、技術Tipsとして価値が高いです。Supabaseユーザーにとって、なぜ代替が選ばれるのかの分析材料になり、ベストプラクティスを考えるきっかけになります。エンゲージメントも高く、開発者コミュニティのトレンドを反映しています。

**投稿内容:**

> データベース侵害（breach）が発生するたびに、なぜかSupabaseが関与しているように感じます。

**解説:**

PlanetScale CEOによる業界分析的な投稿で、Supabaseを使ったプロジェクトでのセキュリティ侵害事例が目立つという指摘です。スレッドの反応では、Row Level Security（RLS）の設定ミスが原因とする声が多く、公式ドキュメントやチュートリアルでRLSの重要性が十分強調されていないとの意見も見られます。SupabaseはオープンソースのFirebase代替として人気ですが、実践的なユースケースでは認証・権限管理のベストプラクティスを厳格に守る必要があることを浮き彫りにしています。業界動向とセキュリティ分析として有益な内容です。
