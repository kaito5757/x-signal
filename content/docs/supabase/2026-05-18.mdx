### 1. SupabaseのData APIデフォルト挙動変更（明示的な権限付与必須化）

| 項目 | 詳細 |
|------|------|
| 投稿者 | Supabase (@supabase) |
| 投稿日時 | 2026年5月18日 00:36（日本時間） |
| エンゲージメント | ❤️ 219 / 🔁 19 / 💬 14 |
| リンク | [元ポスト](https://x.com/supabase/status/2056021013599580203) |

**投稿内容:**

> Supabaseはプラットフォームをより宣言的なコード中心に移行する取り組みの一環として、5月30日以降に作成される新しいプロジェクトでは、publicスキーマの新しいテーブルがData APIに自動的に公開されなくなります。
> 
> 代わりに、テーブルごとに各ロール（anon、authenticatedなど）に対して明示的に権限を付与する必要があります。これはダッシュボードまたはSQLで行えます。
> 
> 明示的なPostgresのGRANTはレビューしやすく、差分確認可能で、検索しやすいという利点があります。また、ロールごとの制御が明確になり、マイグレーションに権限の違いが可視化されます。これまではオプションでしたが、今後はデフォルトになります。
> 
> （スレッド続き：詳細はGitHubの議論を参照）

**解説:**

Supabaseがセキュリティと運用性を大幅に向上させる重要なアップデートを発表しました。これまでは新しいテーブルを作成すると自動的にAPI経由で誰でもアクセス可能な状態になっていましたが、今後は**明示的に権限を付与しない限りAPI公開されない**という「デフォルト拒否」の方針に変更されます。

これは特にAIエージェントがコードを生成する現代の開発環境で重要で、意図せずデータが露出するリスクを大幅に低減します。PostgresのGRANT文をマイグレーションに含めることで、コードレビューやGitでの管理がしやすくなり、長期的なメンテナンス性が向上します。Firebaseからの移行を検討している開発者にとって、Postgresの細やかなアクセス制御の強みを再認識させる内容です。

### 2. AIコーディングエージェントとSupabaseのデータベース分岐機能の連携

| 項目 | 詳細 |
|------|------|
| 投稿者 | Tyler Shukert (@dshukertjr) |
| 投稿日時 | 2026年5月17日 22:01（日本時間） |
| エンゲージメント | ❤️ 115 / 🔁 7 / 💬 13 |
| リンク | [元ポスト](https://x.com/dshukertjr/status/2055997010004647956) |

**投稿内容:**

> Supabaseにはデータベースの分岐（branching）機能があり、AIコーディングエージェントもこれを利用できます！
> 
> 分岐機能により、エージェントは本番環境から完全に隔離された環境でアプリをテストできます。
> 
> SupabaseのMCPとCLIを使えば、AIエージェントは開発フローの中で必要なときに環境を自由に作成・管理できます。

**解説:**

Supabase DevRelエンジニアによる実践的な技術Tipsです。Supabaseの**データベース分岐機能**（本番DBをコピーして独立したテスト環境を即座に作成できる機能）を、AIコーディングエージェント（ClaudeやCursorなどの自動コーディングツール）と組み合わせる方法を紹介しています。

従来、AIエージェントがデータベースのマイグレーションやスキーマ変更を行うと本番環境を壊すリスクがありましたが、分岐を使えば安全なサンドボックスでテスト→検証→本番反映という流れを実現できます。MCP（Machine Control Protocol？）とCLIを活用することで、エージェントに「環境作成権限」を与えつつ、生産性を大幅に向上させるベストプラクティスを具体的に示した投稿で、AIを活用した開発の最先端事例として注目されています。
