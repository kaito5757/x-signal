### 5. Supabaseクエリの最適化：select(*)を避けて必要なカラムだけ取得せよ

| 項目 | 詳細 |
|------|------|
| 投稿者 | zakari ⚛️ (@OyabureZakari) |
| 投稿日時 | 2026年7月13日 16:04（日本時間） |
| エンゲージメント | ❤️ 0 / 🔁 0 / 💬 0 |
| リンク | [元ポスト](https://x.com/OyabureZakari/status/2076563350377345516) |

**投稿内容:**

> データベースからすべてを取得するのはやめよう！
> 
> Supabaseのクエリがアプリの速度を静かに低下させている可能性がある。
> 
> 必要なカラム以外もすべて（パスワードハッシュ、巨大JSON、タイムスタンプ、内部フラグなど）取得している。
> 
> 必要なものだけ取得するメリット：
> - 帯域を大幅削減（特にモバイルや低速ネットワーク）
> - クエリが高速化
> - レンダリングが速くなる
> - コスト低減
> - セキュリティ向上（不要なカラムを露出しない）
> 
> 「.select("*")」を書くたびに「本当に全部必要か？」と自問せよ。
> 
> 習慣化すれば将来の自分とユーザーが感謝する。

**解説:**

Supabase（Postgresベース）でのデータ取得クエリにおける重要なベストプラクティスを解説した技術Tipsです。select(*)の悪影響を具体的に挙げ、必要なカラムだけを指定する重要性を強調。パフォーマンス、コスト、セキュリティの3つの観点から実践的な改善策を示しており、Supabaseを実際に使っている開発者にとって即戦力となる内容です。Firebaseからの移行者も参考にできる、日常的なコーディング習慣の見直しを促す有益な投稿です。
