**投稿内容:**

> Claude Codeを日常的に使うための基本的なTipsをまとめました。
> 
> 1. セッション間で作業スタイルを記憶させたい → /memoryコマンドを使う
> 2. 同じリポジトリで常に同じコンテキスト（プロジェクト規約、ビジネスルール）を保持したい → /initを実行してCLAUDE.mdファイルを作成する
> 3. 編集後に必ずフォーマットを実行したい → /hooksで自動実行ルールを設定
> 4. AIが実行できる操作を制限したい → /permissionsで制御
> 5. 外部ツール、ドキュメント、データベースと連携したい → /mcpコマンドでMCPサーバーを管理
> 6. コードを書く前にまず計画を立てさせたい → /planコマンド
> 7. Opusモデルで計画立案を先行させたい → /model opusplan
> 8. 大きなタスクでメインコンテキストを圧迫したくない → /agentsでサブエージェントを作成して委譲
> 9. 繰り返し作業に決まった手順・基準・出力形式を適用したい → .claude/skillsフォルダにスキル定義を作成（/skillsで確認）
> 10. 会話がコンテキスト上限に達しても同じセッションを続けたい → /compactで圧縮
> 11. タスク間でコンテキストをリセットしたい → /clear
> 12. 推論の深さを調整したい → /effortコマンド
> 
> Claude Codeは単なるモデルではなく、コンテキスト管理・メモリ・ツール・権限・実行ルールという「ハーネス（枠組み）」全体が重要です。この環境をしっかり整えるほど、得られる結果の質が大幅に向上します。

**解説:**

Claude Code（AnthropicのCLIベースAIコーディングツール）の実践的なコマンド一覧とその使い方を体系的に解説した投稿です。単なるプロンプト技ではなく、プロジェクトの長期運用に欠かせない「記憶機能」「自動フック」「サブエージェント委譲」「スキル再利用」などのベストプラクティスを12個紹介しています。初心者から上級者まで、Claude Codeを「ただのコード生成ツール」から「持続可能な開発パートナー」に進化させるための具体的な技術Tipsとして非常に価値が高い内容です。特にCLAUDE.mdやMCP（Model Context Protocol？）の活用は、コンテキスト忘却問題を解決する重要なポイントとして強調されています。

> 
> 特に長期プロジェクトをClaude Codeで進める人、コンテキスト忘却に悩まされている人、大規模プロジェクトでプロンプトが乱雑になりがちな人、AIを「チームの一員」として継続的に働かせたい人に最適です。
> 
> 単独のClaude Codeは「賢いが忘れっぽいプログラマー」のようですが、Trellisを組み合わせることで「本物のAI開発チーム」のような動きを実現できます。
> 
> GitHubリンク: https://github.com/...

**解説:**

Claude Codeの最大の弱点である「コンテキストの忘却」を根本的に解決する外部ツール「Trellis」の導入を強く推奨した投稿です。Trellisがプロジェクト内に専用のディレクトリを作成し、要件定義から進捗ログまでを自動で蓄積・更新する仕組みを丁寧に説明しています。これは新機能というより、実践的なベストプラクティスとユースケースの好例で、長期プロジェクトにおける生産性向上に直結する具体的な成果報告となっています。Claude Codeを「一時的なヘルパー」から「持続的な開発パートナー」に変えるための業界動向的な示唆も含まれており、優先すべき内容に合致します。
