### 4. Claude Codeを「社内シニアエンジニア」にするためのプロジェクト構造化Tips

| 投稿日時 | 2026年5月7日 16:04（日本時間） |

| リンク | [元ポスト](https://x.com/BharukaShraddha/status/2051920978809401584) |

**投稿内容:**

> 多くの人がCLAUDE.mdを単なるプロンプトファイルだと思っている。それが間違いだ。  
> Claude Codeをリポジトリ内に住むシニアエンジニアのように感じさせるには、プロジェクトに適切な構造が必要だ。  
> Claudeは常に以下の4つを必要とする：  
> ・なぜ（システムが何をするか）  
> ・地図（どこに何があるか）  
> ・ルール（許可・禁止事項）  
> ・ワークフロー（作業の進め方）  
>   
> これを「Claude Codeプロジェクトの解剖学」と呼ぶ。  
> 1. CLAUDE.md = リポジトリの記憶（短く保つ）  
> 2. .claude/skills/ = 再利用可能な専門家モード  
> 3. .claude/hooks/ = ガードレール（自動整形・テスト実行など）  
> 4. docs/ = 進行性コンテキスト（アーキテクチャ概要や決定記録）  
> 5. リスクの高いモジュールにはローカルCLAUDE.mdを配置  
>   
> プロンプトは一時的。構造は永続的。このように整理すれば、Claudeはチャットボットではなく、プロジェクトに精通したエンジニアとして振る舞うようになる。

**解説:**

Claude Code（AnthropicのCLIツール）を効果的に使うための実践的ベストプラクティスを、具体的なフォルダ構成とファイル役割とともに解説した技術Tips投稿です。CLAUDE.mdを「リポジトリの記憶」として機能させる方法、skills/hooksを使った一貫性確保、コンテキストの肥大化防止など、実際に大規模プロジェクトでClaude Codeを使う開発者にとって即戦力となるノウハウが満載。優先される「具体的な技術Tips・ベストプラクティス」に合致し、投稿者が自ら構築した構造を体系的にまとめている点が高く評価されます。
