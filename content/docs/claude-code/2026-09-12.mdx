### 1. Claude Codeの新機能「plugin eval」発表

| 項目 | 詳細 |
|------|------|
| 投稿者 | ClaudeDevs (@ClaudeDevs) |
| 投稿日時 | 2026年9月12日 4:56（日本時間） |
| エンゲージメント | ❤️ 2576 / 🔁 135 / 💬 77 |
| リンク | [元ポスト](https://x.com/ClaudeDevs/status/2098500999656923145) |

**投稿内容:**

> Claude Codeの新機能：claude plugin eval  
> プラグインがどれだけ価値を加えているか、または改善が必要かを確認できます。  
> テストケースを作成し、プラグインを使って実行してスコアリングした後、プラグインなしで再度実行して違いを比較します。  
> 
> まずプラグインフォルダで「claude plugin eval init」を実行。Claudeに良い出力と悪い出力の例を伝え、実在のプロンプトをいくつか用意すると、Claudeがテストケースを自動生成します。  
> 次に「claude plugin eval」を実行すると、各ケースのスコア（プラグインあり/なし）と詳細なHTMLレポートが生成されます。  
> 評価にはトークンを使用するため、事前に「--runs 1」でパイロット実行を推奨。信頼できるプラグインのみ評価してください。  
> 「claude update」で最新版に更新し、詳細は公式ドキュメントを参照。

**解説:**

Anthropic公式アカウントによるClaude Code（AnthropicのCLIツール）のアップデート情報です。プラグインやスキル（カスタム機能）の効果を定量的に評価するための新コマンド「claude plugin eval」を紹介しています。この機能は、プラグインが実際に問題解決に寄与しているかを「with/without」比較で測定可能で、開発者がプラグインの質を客観的に判断できるようになります。技術者にとって非常に実践的な新機能で、CI/CDパイプラインへの組み込みも想定されており、Claude Codeのエコシステムを強化する重要なアップデートです。スレッド全体で使い方や注意点が詳細に説明されています。

**投稿内容:**

> 多くの人から「Claudeが書いたコードを本番環境で使ってよいか」という質問を受けます。  
> 私の考えは以下の通りです。  
> 1. プロトタイプや使い捨てコードは黒箱として扱って問題ありません。壊れても影響が小さい場合、完璧である必要はありません。  
> 2. 本番用コードは、人間が書く場合よりも高い品質基準を設けるべきです。Anthropicでは多くのガードレールを導入しています：厳格なlintルール、テスト、ClaudeによるE2Eテスト、ファジングテスト、自動コードレビュー、セキュリティレビュー、自動リファクタリングなどです。これらがないと、後で保守が困難なコードになってしまいます。  
> 幸いモデルはこれらを効率的に行えるようになってきています。日常的にいくつかのルーチンを実行したり、Claude Code Reviewを使ったりしてください。  
> あなたの役割はコード品質の基準を守ることです。基準を満たさない場合は、最新の最先端モデル（Opus 5やFable 5.1）を使う、effortをhigh/xhighに上げる、CLAUDE.mdやスキルに十分な指示を入れるなどの対策を。  
> それでも難しい場合は、Claudeに技術的負債を解消させたり、コードベース全体を書き直させたり、次期モデルを待つことを検討してください。

**解説:**

AnthropicのClaude Code担当者による、実践的なベストプラクティスと業界動向を示す投稿です。Claude Codeで生成したコードを本番環境で使う際の品質管理について、Anthropic社内での実際の取り組みを基に詳述しています。プロトタイプと本番コードを明確に区別し、後者には自動化された厳格なチェック体制を推奨しており、単なる生成ツールではなく「責任あるAIコーディング」の指針となっています。CLAUDE.mdの重要性やeffortレベルの調整など、すぐに活用できる具体的なTipsが満載で、Claude Codeを本格的に業務で使う開発者にとって非常に価値の高い分析です。
