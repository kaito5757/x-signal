### 1. Claude Codeのコンテキストエンジニアリングの新ルール（システムプロンプト80%削減）

| 項目 | 詳細 |
|------|------|
| 投稿者 | Thariq (@trq212) |
| 投稿日時 | 2026年7月25日 2:45（日本時間） |
| エンゲージメント | ❤️ 5134 / 🔁 478 / 💬 158 |
| リンク | [元ポスト](https://x.com/trq212/status/2080710971228918066) |

**投稿内容:**

> 最新のClaude 5世代モデル向けに、Claude Codeのシステムプロンプトを80%以上削減した結果、学んだコンテキストエンジニアリングのベストプラクティスをまとめました。これをClaude Code内で`/doctor`コマンドを使って自分のスキルやCLAUDE.mdファイルに適用できます。
> 
> **過去の常識から新しいアプローチへ:**
> - 厳格なルールを与える → モデルに判断を委ねる（例: 「コメントを書くな」ではなく「周囲のコードのコメント密度に合わせる」）
> - ツールの使用例を与える → ツールのインターフェース自体を表現豊かに設計する
> - すべて最初にまとめて提示 → 進行性開示（必要なときにスキルやツールを動的にロード）
> - 指示を繰り返す → ツール記述だけに簡略化
> - CLAUDE.mdに記憶を保存 → 自動メモリ機能を使う
> - シンプルなMarkdown仕様 → HTMLアーティファクトやテストスイート、別コードベースの関数などのリッチな参照を使う
> 
> CLAUDE.mdはリポジトリの「落とし穴」だけを簡潔に記述し、明白なことはモデルに任せる。長いスキルは複数のファイルに分割して必要なものだけロード。システムプロンプト、スキル、CLAUDE.md全体をシンプルに保つことが重要です。詳細はClaudeブログの「The New Rules of Context Engineering for Claude 5 Generation Models」を参照。

**解説:**

AnthropicのClaude Code開発者であるThariq氏が、最新モデル（Opus 5など）でシステムプロンプトを大幅に削減できた背景と、その過程で発見したコンテキストエンジニアリングの原則を詳細に解説したスレッドです。過去はモデルが未熟だったため厳しいルールや繰り返し指示が必要でしたが、賢くなったモデルには過剰な制約が逆効果で、判断を委ねたりツール設計を重視したりする方が効果的だと指摘。実践的なアドバイスとして`/doctor`コマンドの活用やCLAUDE.mdの軽量化を推奨しており、Claude Codeユーザーにとって即適用可能な技術Tipsとして非常に価値が高い内容です。スレッド全体を通じて、モデル進化に伴うプロンプト設計のパラダイムシフトをわかりやすく説明しています。
