### 3. Dynamic Workflowsの実測テスト結果（8エージェントで253kトークン）

| 項目 | 詳細 |
|------|------|
| 投稿者 | Paweł Huryn (@PawelHuryn) |
| 投稿日時 | 2026年5月29日 03:18（日本時間） |
| エンゲージメント | ❤️ 120 / 🔁 6 / 💬 5 |
| リンク | [元ポスト](https://x.com/PawelHuryn/status/2060063258527088984) |

**投稿内容:**

> Claude Codeの新dynamic workflowsを実際にテストしました。8エージェントを24.5秒で起動、253kトークンを使用。  
> 発表では「大規模な協調サブエージェント艦隊」と表現されていますが、これはSDKですでに数年前から可能でした。  
> 本当の新しさはオーケストレーターの実行場所にあります。ClaudeのターンではなくJavaScriptで動作するため、モデルトークンを消費しません。  
> 各サブエージェントは独立したコンテキスト、ツール、中間呼び出しを持ち、親スレッドには戻り値のみが渡されます。8つの全文トランスクリプトや50kトークンのノイズではなく、単一のオブジェクトだけです。  
> 20エージェントの監査では、隔離されたエージェント間で600kトークンを使い、2kトークンの統合結果だけを返します。従来は「包括的なレビュー」を行うと、修正に必要なコンテキストまで埋まってしまいました。  
> スクリプトは.claude/workflows/\<name>.jsに永続化され、名前と引数で呼び出せます。cronスケジュール可能で1段階深く構成できます。関数ライブラリのようです。  
> これまではサブエージェントを「コンテキスト隔離」として扱っていましたが、Dynamic Workflowsはそれを「委譲」へと進化させ、一つのエージェントから艦隊へと移行します。  
> 単なるファンアウトではなく、混乱は親スレッドの外に留めます。

**解説:**

AIプロダクトマネージャーがClaude Codeの新機能を実際に動かして検証した技術的深掘り投稿です。発表内容と既存SDK機能の違いを明確にし、オーケストレーターをJavaScriptで実行することでトークンを節約し、各エージェントのコンテキストを完全に隔離する仕組みを詳細に解説しています。実測値（8エージェント/24.5秒/253kトークン、20エージェント時の600k→2kトークン圧縮）や永続化・cron対応などのベストプラクティスを具体的に共有しており、技術Tips・ベストプラクティスとして極めて優先度の高い内容です。読者がすぐに試せる実践的な知見が豊富です。
