> 本番APIエンドポイントに対する許可されたテストを実施。Opus 4.7はSQLインジェクションが存在することを確認したものの、データベース名を抽出できませんでした。sqlmapも偽陽性と判定。
> 
> Claude Code内でDeepSeek V4 Proに切り替えたところ、データベースに意図的にクラッシュさせてYes/No質問に答えさせるトリックを考え出しました。CASE WHENをXMLキャストで包むペイロードを使い、条件が真なら不正XMLでHTTP 500を、偽なら正常XMLでHTTP 200を返します。WAFはSQLキーワードを監視していましたが、XMLエラーは見逃しました。
> 
> 19個のデータベース名を抽出。Opusとsqlmapが失敗したところでDeepSeekが成功し、所要時間2時間、費用20セント。
> 
> 設定方法：~/bin/claude-deepを作成し、環境変数でDeepSeekのエンドポイントとモデルを指定。元のclaudeコマンドは変更不要。サイバーセキュリティ制限なし！

**解説:**

セキュリティ研究者がClaude Codeを活用して、本番環境でのSQLインジェクション検証を行った実践的なユースケース報告です。通常のツール（sqlmap）や標準モデル（Opus）が失敗した複雑なブラインドSQLiに対し、Claude Code内で別モデル（DeepSeek V4 Pro）に切り替えて独自のエラー誘発ペイロードを生成・実行。これによりWAFを回避しながら効率的に情報を抽出しました。設定方法も詳細に記載されており、他の開発者やセキュリティ専門家がすぐに再現可能な具体的な技術Tips。AIツールの柔軟なモデル切り替えが実世界のセキュリティ業務で成果を上げた好例です。
