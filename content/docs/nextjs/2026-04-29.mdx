**投稿内容:**

> Next.jsもプロトコルを標準化する側で開発が進んでいたら使い続けていたのだが、RSC（React Server Components）がVercelロックインを強める方向にしか機能しないため、もう諦めている。
> 新規プロジェクトでの採用はもうない。過去の設計上の失敗という負債の重みで死に体になっている。

**解説:**

著名フロントエンドエンジニアのmizchi氏が、Next.js（特にReact Server Components＝RSC）の設計について厳しい分析をした投稿です。RSCがオープンな標準プロトコルとして進化するのではなく、Vercelのプラットフォームに開発者をロックインさせる方向に設計されている点を問題視しています。これにより「過去の設計失敗の負債」が積み重なり、新規採用を止めたという実践的な判断を述べています。技術的な背景として、React Server Componentsはサーバー側でコンポーネントをレンダリングすることでパフォーマンスを向上させる機能ですが、その実装がVercelのエコシステムに強く依存しているという業界内の議論を象徴しています。単なる不満ではなく、標準化 vs ロックインという技術戦略の観点から分析しており、業界動向・技術選択のベストプラクティスを考える上で非常に示唆に富んだ内容です。Likes100超えの基準を満たす中で、具体的な技術的意見として優先度が高いと判断しました。
