### 3. Vercel BlobがS3互換でない理由についての議論

| 項目 | 詳細 |
|------|------|
| 投稿者 | Christoffer Bjelke (@chribjel) |
| 投稿日時 | 2026年5月5日 17:27（日本時間） |
| エンゲージメント | ❤️ 136 / 🔁 0 / 💬 15 |
| リンク | [元ポスト](https://x.com/chribjel/status/2051579506511495611) |

**投稿内容:**

> why is Vercel Blob not S3 compatible???
> 
> （スレッドの続きとしてVercel CTOのMalte Ubl氏が回答）
> 
> We felt that there is space to innovate on the API for web-facing use cases (e.g. for reliable, concurrent upload). We don't take such divergences lightly.
> 
> I agree that there should be an S3 compatible API. Thing is: we're on AWS. You can just use S3 directly
> 
> （さらに複数の開発者からベンダーロックイン懸念や代替案（Cloudflare R2など）の意見が寄せられている）

**解説:**

Vercelのストレージサービス「Vercel Blob」がAmazon S3と互換性がないことに対する疑問を投げかけた投稿で、多くの開発者から共感と議論を呼んでいます。VercelのCTOであるMalte Ubl氏が直接返信し、ウェブ向けのユースケース（同時アップロードの信頼性など）でAPIを革新したい意図を説明するとともに、S3互換APIの必要性は認めつつ、AWS上で直接S3を使う選択肢もあると回答しました。このやり取りはNext.jsアプリケーションでファイルストレージを選択する際のベンダーロックイン問題やアーキテクチャ判断の重要性を浮き彫りにしており、実践的な業界動向として参考になります。
