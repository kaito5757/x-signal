### 1. TypeScript 7.0のGo言語コンパイラとWebStormの対応計画

| 項目 | 詳細 |
|------|------|
| 投稿者 | WebStorm, a JetBrains IDE (@WebStormIDE) |
| 投稿日時 | 2026年5月21日 21:55（日本時間） |
| エンゲージメント | ❤️ 123 / 🔁 3 / 💬 3 |
| リンク | [元ポスト](https://x.com/WebStormIDE/status/2057445246435229948) |

**投稿内容:**

> TypeScript 7ではGo言語で書かれた新しいコンパイラが導入されます。現在のコンパイラの10倍の速度になりますが、最初は拡張APIをサポートしません。
> 
> WebStormはこれを待たずに、オープンソースのフォークを構築してAngular、Vue、React向けの初日から使えるブリッジを提供します。
> ここではPRではなく、実際のエンジニアリング計画をお伝えします。
> 
> （スレッド続き）まず「拡張API非対応」とは何かを説明します。現在、WebStormなどのIDEはTypeScriptの言語サービスに拡張APIを使って接続し、型チェック、補完、リファクタリングなどを実現しています。TS Go版ではこれがまだ提供されていません。Microsoftが開発中ですが、時期は未定です。
> 
> そこでWebStormはTypeScript Goコンパイラのフォーク（Apacheライセンスのオープンソース）を作成し、LSPサービス（ハイライト・補完）と型評価（SPTE）を1つのTypeScriptプロセスにバンドルします。
> 
> このフォークはJavaScriptプラグインに直接バンドルされ、インストール不要で自動更新されます。node_modulesでTS 7.0が検出されるとデフォルトで有効になります。
> 
> すでにEAP（早期アクセスプログラム）で試せます。設定から「TypeScript-Go JetBrains Fork」を選択してください。ファイルを開いたときの初期解析速度が大幅に向上します。
> 
> フレームワーク別対応：AngularはKolarスタイル統合、VueはGolar、非主要フレームワークはLSPへ移行、Reactはデフォルトのままフォーカス。
> 
> この計画はMicrosoftの拡張API公開時期に依存します。フォークは一時的な橋渡しで、APIが揃ったら公式の上流に移行します。多くのツールがTS 7.0で動作しなくなったり待機する中、WebStormは初日からサポートを提供する準備ができています。

**解説:**

TypeScript 7.0で大きな性能向上が発表されました。コンパイラをGo言語で全面的に書き直すことで、型チェックなどの処理が現在の10倍高速化される見込みです。ただし、IDEが深く統合するために使っている「拡張API」が当初サポートされないため、既存の開発環境に影響が出る可能性があります。
この投稿ではJetBrainsのWebStormチームが、Microsoftの公式対応を待たずに独自のオープンソースフォークを準備している具体的な計画を詳細に解説しています。フォークは一時的なもので、最終的には公式APIに移行する方針です。開発者にとって、TypeScriptの大型アップデート時のIDE互換性という実践的な課題に対する具体的な解決策を示した内容で、業界動向と技術的準備の両方をカバーしています。

> C tier: PHP、Haskell、Scala

**解説:**

プログラミング言語をユーモアを交えて「セクシーさ」という主観的な基準でランク付けした投稿です。GoやRustのようなシステム寄り言語が高評価を受ける一方で、TypeScriptは「cringe（気恥ずかしい）」という最下層に位置づけられています。
これはTypeScriptが広く使われている実用的な言語である一方で、JavaScriptの「型付けされたバージョン」という位置づけが、純粋な新言語としての魅力に欠けると見なされていることを反映した業界内のジョーク的な分析と言えます。TypeScriptの普及度とイメージのギャップについて、軽い形で業界動向を垣間見られる内容です。
